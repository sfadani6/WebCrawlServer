# 작업 이력: best-of-red 안정 우선 재설계 — 0페이지부터 전체 순회 + 실제 미디어 다운로드 + 저장 ACK 확인 후 이동 (ask-20260810225335)

## 요청 (사용자 지시 원문)
- 왜 16페이지부터 시작하지 0번부터 아냐? → **0번부터 전체 순회**해야 한다.
- 각 페이지에서 `.thumb-block` 내 이미지(메인/보조 썸네일)와 `.videopv video`의 **프리뷰 mp4를 추출**해야 한다 (JSON URL만이 아니라 **실제 다운로드**).
- 페이지 이동을 HTML 문서만 로드되면 바로 하지 말고, **실제 브라우저의 네트워크/XHR까지 감시해 로드 완료 상태를 검증**한 뒤 페이지 정보를 완벽하게 수집·파일 다운로드를 완벽하게 하고, **다시 한번 검증한 후 다음 페이지로 이동**해야 한다.
- 총 이동할 페이징 정보를 **배열로 저장**해 하나씩 이동하면서 정보 수집·다운로드 완료 확인 후 다음 페이지로 이동하는 **안정된 플로우**를 가져야 한다.
- (사용자 확정) 썸네일+preview **실제 다운로드 저장**, 0건이어도 **빈 JSON 저장**.

## 재설계 핵심
- **페이지 범위**: 기존 `currentPage(16)..maxPage` → **`pageList = 0..maxPage` 전체 순회**(`totalPages = maxPage + 1`). 0은 베이스 URL(`/best-of-red/<월>`).
- **페이지당 안정 플로우(ACK 확인 후에만 다음 이동)**:
  1. `chrome.tabs.update` + `chrome.tabs.onUpdated` complete + 경로 일치 대기(30초)
  2. `COLLECT_BEST_OF_RED_PAGE` 수집 — 로드 검증(네트워크 안정+DOM 안정+이미지 완료) 실패/0건 시 최대 3회 재시도(1초 간격)
  3. **미디어 실제 다운로드** — `requestFetchPageMediaBundles()` → 오프스크린이 동시성 3 제한으로 엔트리별 3자산 fetch → `CRAWL_IMAGE` 번들(`pathSegments` 포함) 저장 → `CRAWL_MEDIA_SAVED` ACK 확인
  4. **JSON 저장** — `CRAWL_PARTIAL`(requestId 포함) → 서버 `CRAWL_PARTIAL_SAVED` ACK(실제 파일 경로) 확인 → 5. 600ms 대기 후 다음 페이지

## 확인된 동작 규칙 (검증 대상)
- **0부터 전체 순회**: `totalPages = maxPage + 1`, 액션 실행기 팝업이 0(베이스)부터 +1씩 전체 페이지를 순회한다.
- **저장 ACK 확인 후 이동**: `CRAWL_PARTIAL_SAVED` ACK(실제 파일 경로/크기)와 각 미디어 번들 `CRAWL_MEDIA_SAVED` ACK를 확인한 뒤에만 다음 페이지로 이동한다.
- **0건 페이지도 빈 JSON 저장**: 수집 항목이 0건이어도 `data: []` JSON을 저장한다.
- **실패 집계**: 수집 재시도 초과/미디어 실패/JSON 저장 실패 시 페이지 실패로 집계되고 완료 배너에 표시된다.
