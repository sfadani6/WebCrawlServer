# 작업 이력: best-of-red 수집 정확도 재설계 — 기대 URL 검증 + 강제 렌더링(스크롤) + 네트워크 상태 모니터링 + 페이지별 트리 로그 UI (ask-20260811001627)

## 요청 (사용자 지시 원문)
- 페이지당 수집건이 기본 28건 정도여야 하는데 **왜 12건만 수집**되는가? → 이전 페이지와 새로 이동한 페이지 정보를 제대로 구분하지 못하고, **새 페이지 브라우저 로드 완료를 확인하지 못하는 것**으로 판단.
- HTML만 분석해도 27~8건은 나올 텐데 제대로 분석하지 못하고 있다. `데이터 수집 중... (시도 2/3)`이 나오는 건 **브라우저가 페이지 로드를 완료했는지 기다리는 로직이 없다**는 뜻.
- 브라우저 해당 탭의 **브라우저 상태를 검증**하고 페이지를 분석·수집할 내용을 정리해야 한다. 1~n 페이지를 이동하며 수집·다운로드할 때 **브라우저의 네트워크 상태를 모니터링**해야 한다.
- (추가) 팝업 창 진행 표시를 **페이지별 트리 구조**(1페이지 `ul` 아래 작업들, n페이지 `ul` 아래 작업들)로 **열고 펼칠 수 있게** 변경해야 한다. 아니면 몇 번째 작업인지 확인하기 어렵고 페이지 스크롤이 너무 길어짐.

## 원인 진단
- **12건 수집 원인**: 백그라운드 탭에서는 화면 밖(viewport 밖) lazy 로드 블록이 렌더되지 않아 첫 화면 ≈12건만 DOM에 존재 → 이후 전체 항목을 수집해도 12건.
- **로드 완료 미검증**: 기존 검증이 `img.complete && naturalWidth > 0`에 의존해 백그라운드 탭에서는 썸네일 로드가 늦어 검증이 지연·실패(시도 2/3 로그), 반대로 이미지가 먼저 떠도 실질 로드는 계속 진행 중일 수 있었음.
- **이전/새 페이지 구분 실패**: 이동 후 검증 시 기대 URL(경로) 일치를 확인하지 않아 이전 페이지 상태를 새 페이지로 오인할 수 있었음.
- **네트워크 감시 누수**: XHR을 `open()` 기준으로 카운트해 초기 요청이 감시되지 않거나(주입 시점), 한 번 오른 카운트가 남는 누수가 있었음.
- **이중 폴더 버그**: 실측 저장 경로에 `images/common/best-of-red/best-of-red/<월>/<N>/` 이중 폴더가 생성됨.
- **플레이스홀더 썸네일**: lazy 로드로 썸네일이 아직 로드되지 않으면 `src`가 `no-img`/1×1 gif 같은 플레이스홀더여서 URL 수집이 누락될 수 있었음.

## 처리 단계
1. `plugins/basic-plugin/src/content.ts`:
   - `installNetworkActivityWatch()` 재작성: XHR은 **`send()` 시점 +1 / `loadend`(once) 시점 -1**로 카운트(open 기준 누수 제거), fetch 유지. manifest `run_at: "document_start"`로 **초기 요청부터 감시**.
   - `waitForXvBestOfRedPageReady(expectedPath)` 재작성: ① 기대 URL 검증(`expectedPath` 불일치 시 `ready: false`+사유, 8초 폴링) ② `readyState === "complete"` ③ **강제 렌더링**(`forceRenderBestOfRedContent()` lazy→eager·data-src→src + `forceScrollThroughPage()` 2초 간격 재스크롤, 끝 도달 시 맨 위 복귀) ④ DOM 안정(블록 수 3연속 동일) ⑤ 네트워크 안정(인플라이트 0 + 리소스 3연속 동일). **이미지 로드 조건 제거**. 백그라운드 탭은 폴링 800ms·데드라인 35초 보정.
   - 응답에 `network: { inflight, resources, stable }`·`waitedMs`·`visibilityState` 포함.
   - `resolveImageSource()` 재작성 + `isPlaceholderUrl()` 신규(no-img/about:blank/1×1 gif 무시, data-src 계열 우선).
2. `plugins/basic-plugin/src/types/index.ts`: `XvBestOfRedPageData`에 `network`/`waitedMs`/`visibilityState` 추가.
3. `plugins/basic-plugin/src/services/chromeService.ts`: `requestXvBestOfRedPage(tabId, expectedPath)`로 기대 경로 전달, `requestFetchPageMediaBundles` 실패 분기에 `entryFiles: []` 추가.
4. `plugins/basic-plugin/src/hooks/useBestOfRedRunner.ts`: `ActionRunnerLog`에 `page: number | null` 그룹 키 추가, 로드 검증 대기 로그("브라우저 로드 검증 대기 중...(네트워크 모니터링)") + 검증 완료 로그(네트워크 안정·인플라이트·리소스·대기 시간·블록 수), `ready=false` **2회 연속 시 `chrome.tabs.reload()` 후 재대기**.
5. `plugins/basic-plugin/src/components/ActionRunnerView.tsx` **전면 재작성**: 페이지 등장순 그룹 + 전역(`__global__`) 그룹 트리, 그룹 헤더 ▾/▸ + 배지(오류>경고>완료) + 로그 수, **현재 페이지 자동 펼침 + 자동 스크롤**, "전체 펼치기/접기" 토글.
6. `plugins/basic-plugin/src/offscreen.ts`: `handleFetchPageMediaBundles()`에서 `pathSegments[0] === "best-of-red"`이면 **`slice(1)`로 중복 세그먼트 제거**(이중 폴더 버그 수정).
7. `plugins/opera-plugin` 7종 동기화(manifest 포함, diff 0) + 양 플러그인 빌드 성공(각 56 모듈) + server `npx tsc --noEmit` 통과 + 루트 eslint 플러그인 이슈 0건 + pm2 재시작(포트 9600 HTTP 200).
8. 문서: R-00430 §5.5+§6(기대 URL 검증·강제 렌더링·send 기반 네트워크 감시·이미지 로드 불요·응답 규격·트리 로그·이중 폴더), R-00420 §4.5(COLLECT_BEST_OF_RED_PAGE·FETCH_PAGE_MEDIA_BUNDLES), R-00440 §2.4+체크리스트(페이지별 트리 로그 UI), askLog 신규(ask-20260811001627), ask.md 초기화.

## 확인된 동작 규칙 (검증 대상)
- **기대 URL 검증**: 이동 후 수집 전에 `expectedPath`(예: `/best-of-red/2026-07/1`)와 현재 pathname이 일치하는지 8초 동안 폴링 확인. 불일치 시 `ready: false` + 사유로 반환.
- **강제 렌더링(비침입적 강제 스크롤)**: 콘텐츠 스크립트가 lazy→eager·data-src→src 복사 후 2초 간격으로 페이지를 강제 스크롤(끝 도달 시 맨 위 복귀)해 백그라운드 탭에서도 화면 밖 블록이 렌더되도록 유도 → 전체(≈27건) 블록 수집.
- **네트워크 상태 모니터링**: `pageInflightCount === 0` + 리소스 엔트리 연속 3회 동일을 만족해야 완료. 로그에 인플라이트/리소스/대기 시간이 표시됨.
- **이미지 로드 불요**: 완료 판정에 썸네일 로딩을 요구하지 않음(URL은 HTML 속성에서 추출, 실제 다운로드는 오프스크린 fetch). 백그라운드 탭 지연 문제 제거.
- **재시도 보강**: `ready=false` 연속 2회 시 탭 새로고침 후 재대기, 총 3회 시도 후 실패 집계.
- **트리 로그 UI**: 페이지 번호별 그룹으로 로그를 펼침/접기, 현재 작업 페이지 자동 펼침·자동 스크롤, 상단 배지(오류>경고>완료) + 로그 수 표시.
- **이중 폴더 제거**: best-of-red 미디어가 `images/common/best-of-red/<월>/<N>/` 단일 폴더에 저장됨.
