# 작업 이력: xvideos 다운로드 매니저 새창 페이지 전체 스크롤 (ask-20260810065244)

## 요청
- "xvideos 다운로드 매니저 새창이 스크롤 될게 해달라고 아래 데이터를 확인 할수가 없어"

## 확정된 결괏값
- 매니저 창을 **페이지 레벨로 통째로 스크롤** — 목록·버튼·로그를 포함한 아래 데이터까지 항상 확인 가능.
- 원인: `popup.css` 전역 `html, body { overflow: hidden }`이 매니저 페이지에도 적용되어 페이지 스크롤이 원천 차단된 상태였음.

## 처리 단계
1. `plugins/basic-plugin/xvideos-manager.html`: `<html lang="ko">` → `<html lang="ko" class="manager-scrollable">` (Vite가 빌드 시 클래스 유지, dist 반영 확인).
2. `plugins/basic-plugin/src/popup.css`: `html.manager-scrollable { overflow-y: auto }` + 웹킷/파이어폭스 가시 스크롤바(thumb `#475569`·hover `#64748b`, track `#0a0e17`) 추가 — 클래스 선택자가 전역 `html` 규칙보다 높은 특이성으로 우선 적용.
3. `plugins/basic-plugin/src/components/XvideosManagerView.tsx`: 루트 `w-full h-screen … overflow-hidden` → `w-full min-h-screen …`(overflow-hidden 제거), 목록 컨테이너에서 `flex-1 min-h-0 overflow-y-auto` 제거 → 자연 높이로 펼쳐지고 창 스크롤로 전 항목 도달.
4. `plugins/basic-plugin/src/xvideosManager.tsx`: 로딩/에러 뷰의 `h-screen` → `min-h-screen` 통일.
5. **opera-plugin 동기화**: `xvideos-manager.html`/`popup.css`/`XvideosManagerView.tsx`/`xvideosManager.tsx` 4종 헤더 교체 복사.
6. **문서 마감**: R-00440 §2.3(페이지 전체 스크롤 규격), R-00430 §5.4, askLog 신규, todo.md/history.md 반영.
