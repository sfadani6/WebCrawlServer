# 작업 이력: 플러그인 DOM 액션 개편·이미지 수집 3버튼 + admin DB 정렬/필드검색/SQL 예제 (ask-20260810024611)

## 요청
- 플러그인의 [현재 페이지 전체 DOM 전송]이 페이지 이전 소스가 아닌 **버튼을 누를 때 현재 렌더링된 DOM을 다시 전체 읽어 전송**하도록 하고, 전체 페이지 액션명은 `CRAWL_DOCUMENT` → `fullPage`, DOM 요소 전송은 `DomCapture`로 개편.
- 이미지 수집 버튼을 3군데 구성: ① 일반 이미지 수집 ② `xchina.co` — 일반/앨범/표지/정보 수집 ③ `xvideos.com` — 일반/정보 수집. 서버는 이미지를 기본 저장 경로에 **도메인별 디렉토리 구분**으로 저장(일반은 `normal`).
- admin DB 관리의 테이블 rows에서 `client_id|timestamp|action|domain|worker_name|url` 등의 컬럼 옆에 **오름차순/내림차순 화살표**로 소팅.
- 행 검색(LIKE) 입력 앞에 **각 테이블의 필드 선택 드롭다운**을 배치하고, 선택한 필드에 대해서만 LIKE 검색.
- SQL 실행기에 **예제 샘플 20가지 드롭다운** — 선택 시 에디터에 쿼리 문장이 삽입되어 사용자가 수정·실행.

## 확정된 상세 규격 (사용자 협의)
- 액션 명칭: 전체 페이지 document/iframe → `fullPage`, 요소 선택 outerHTML → `DomCapture`. 구형 `CRAWL_DOCUMENT`/`CRAWL_PARTIAL`은 **계속 수용(하위 호환)**. 크로스오리진 iframe src 참조는 기존 `CRAWL_PARTIAL` 유지.
- 이미지 저장 규격: `<기본경로>/images/<도메인>/<카테고리>/<timestamp>-<seq>.<ext>`, 카테고리는 `normal`/`album`/`cover`(기본 `normal`). 사이트 전용 버튼은 **범용 수집 + 카테고리 저장**(선택자 불필요). 정보 수집은 `SITE_INFO` 액션으로 메타(description/keywords/og/canonical 등) JSON을 `<기본경로>/images/<도메인>/info/<ts>-<seq>.json`에 물리 저장.
- 사이트 매칭: `matchSiteDomain()` — 호스트 정확 일치 또는 `.도메인` 접미사. `xchina.co` → [normal, album, cover, info], `xvideos.com` → [normal, info].
- 정렬/검색 규격: `fetchTableRows` 신규 파라미터 `searchField`/`orderBy`/`orderDir`(asc|desc). 컬럼명은 PRAGMA `table_info` 기반 화이트리스트 검증, `%`/`_` LIKE 이스케이프(`ESCAPE '\'`), ORDER BY는 SELECT 앞에 삽입(캡 유지 최대 200). 필드 미지정 시 기존 전체 컬럼 OR LIKE. **데이터 브라우저는 서버 정렬, SQL 결과 그리드는 클라이언트 정렬**.
- 테이블 변경 시 검색어/검색 필드/정렬/페이지 리셋.

## 처리 단계
1. **플러그인(basic-plugin 5파일 + popup.tsx)**: `content.ts` — 요소선택 `CRAWL_PARTIAL`→`DomCapture`, iframe 전체문서 `CRAWL_DOCUMENT`→`fullPage`, `COLLECT_FULL_DOM`→`fullPage`(outerHTML 재캡처). `collectAndSendImages(category="normal")` 페이로드에 `category` 추가. 신규 `collectAndSendSiteInfo()` → `SITE_INFO`. 리스너: `COLLECT_IMAGES` payload.category 파싱 + 신규 `COLLECT_SITE_INFO`. `chromeService.ts` — `requestCollectImages(category)`/`requestCollectSiteInfo()`. `usePopupState.ts` — `handleCollectImages(category)`/`handleCollectSiteInfo()`. `BasicTab.tsx` — `matchSiteDomain()`/`CATEGORY_LABELS`/`SITE_IMAGE_BUTTONS`, 일반 버튼 상시 + matchedSite 시 사이트 전용 그리드. `sidepanel.tsx`/`popup.tsx` — props 체인.
2. **서버 저장/액션**: `fileStorageService.ts` — `SaveCrawledImageOptions.category?` + `saveCrawledImage` `images/<도메인>/<카테고리>` 삽입, 신규 `saveSiteInfoToFile` → `images/<도메인>/info/<ts>-<seq>.json`. `index.ts` — 액션 허용 목록에 `fullPage`/`DomCapture`/`SITE_INFO` 추가, `CRAWL_IMAGE` category 전달, 신규 `SITE_INFO` 분기(JSON 물리 저장 + crawl_logs), 워커 파이프라인 조건 `CRAWL_DOCUMENT || fullPage`로 확장. `useAdminSocket.ts` — 실시간 액션 목록에 신규 액션 추가.
3. **서버 fetchTableRows 확장**: `dbManagerService.ts` — 시그니처 `(dbRel, tableName, page=1, size=20, search="", searchField="", orderBy="", orderDir="asc")`. 컬럼 화이트리스트 검증, 필드 단일 LIKE/전체 OR LIKE + `ESCAPE '\'`, `ORDER BY <col> ASC|DESC`, COUNT/SELECT에 whereClause/orderClause 삽입. `index.ts` `/api/admin/db/rows` 라우트에 3개 쿼리 파싱 추가.
4. **admin 데이터 브라우저 정렬/필드검색**: `dbApiService.fetchTableRowsApi` 8파라미터 확장, `useDbManager.loadRows` 확장, `DbBrowserPanel` — 검색 필드 드롭다운(전체 필드 + 스키마 컬럼)·정렬 상태·테이블 전환 리셋, `DbDataGrid` — `sortColumn/sortDir/onSortChange` prop + 헤더 클릭 정렬(▲`arrow_upward`/▼`arrow_downward`/미정렬`unfold_more`).
5. **admin SQL 예제 + 클라이언트 정렬**: `SqlQueryPanel` — `EXAMPLE_QUERIES` 20개 드롭다운(선택 시 에디터 삽입, 자동 실행 없음), `DbDataGrid` `clientSort` prop(숫자 수치 비교/문자열 localeCompare, 토글).
6. **opera-plugin 동기화**: 변경 6종(content.ts, chromeService.ts, usePopupState.ts, BasicTab.tsx, sidepanel.tsx, popup.tsx) 복사 + 헤더 경로만 `plugins/opera-plugin/src/` 교체. 양 플러그인 `npm run build` 성공.
7. **문서**: R-00203(rows API searchField/orderBy/orderDir + LIKE 이스케이프 규격), R-00304(§3.1 기능 탭·§3.3 필드검색/헤더정렬/SQL 예제+클라이언트정렬 규정·체크리스트) 갱신.
