# R-013 예외 처리 및 보안 규정 (security.md)

> 작성자: 사용자

> 본 프로젝트는 1인 개인용 로컬 도구다. 아래는 최소한의 예외 처리/오류 추적 규정만 다루며, 인증·권한 분리·암호화 등 다중 사용자/외부 노출 환경에 필요한 보안 장치는 포함하지 않는다. 실제로 외부 공개나 다중 사용자 지원이 필요해지는 시점에 별도로 논의하고 이 문서를 다시 작성한다.

---

- 모든 실행은 반드시 로그에 기록되며, 누락 시 시스템 경고를 발생시킨다.
- 모듈/워크플로우 실행 실패 시 `error_logs`에 상세 메시지를 기록한다.
- 실패한 작업은 최대 3회까지 자동 재시도한다. 3회 초과 시 로그에 실패로 기록한다(개인용 도구이므로 별도 관리자 알림 채널 없이 Slack Webhook만 사용).
- API 키 등 외부 서비스 연동 정보는 평문으로 로컬에 저장해도 무방하다. 단, 저장 파일(`config.json` 등)은 `.gitignore`에 포함해 저장소에 올라가지 않도록 한다.
- 로컬 프로그램 실행(`run_process`)은 본인만 사용하므로 화이트리스트나 별도 승인 절차 없이 실행을 허용한다. 실행 이력은 `activity_logs`에 남겨 사후 확인만 가능하게 한다.
- 모듈 스키마 생성/변경(`database.md` 2장)도 별도 검증 절차 없이 적용한다. 적용 이력은 `activity_logs`에 남긴다.
- 스케줄러(`scheduler.md`, R-005)가 등록한 작업의 실행 실패도 위 재시도/기록 규정을 동일하게 따른다.
