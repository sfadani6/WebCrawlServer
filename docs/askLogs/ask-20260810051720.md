# 작업 이력: xvideos.com 미디어 다운로드 매니저 — txt 참조 저장·3자산 번들 저장·DownloadThemAll식 목록 UI (ask-20260810051720)

## 요청
- "xvideos.com 이미지 수집 시 `.url` 참조 파일 대신 `.txt` 파일로 저장되게 하고, txt에 `click_url`/`title` 메타를 수집해서 추가하고 싶다."
- "실제 이미지(`xv_24_t.jpg` 메인·`xv_3_t.jpg` 보조)와 프리뷰 `preview.mp4`를 플러그인에서 서버 저장 위치를 받아 직접 다운로드해 저장하고 싶다. 서버 다운로드는 차단되고 오페라 브라우저 VPN 기능이 있으므로 오페라 플러그인에서 직접 내려받아 저장하는 방식을 쓰겠다."
- "다운로드 상한 없이 DownloadThemAll처럼 다운로드 목록을 만들고 진행 버튼을 누르면 순차 다운로드하면서 완료 표시, 동일 주소 중복 제거를 원한다."

## 확정된 상세 규격 (사용자 협의)
- 흐름: 콘텐츠 스크립트가 `.thumb-block` 전량 파싱(상한 없음, `no-img.png` 제외, clickUrl 중복 제거) → 사이드바 목록 UI → [진행] 시 오프스크린이 3자산 fetch(CORS 우회 + 오페라 VPN) → `CRAWL_IMAGE` 번들(assets[3] + txtContent) WebSocket 전송 → 서버가 `images/xvideos.com/normal/<ts>-<seq>.txt` + `<baseName>_thumb/sfw/preview.<ext>` 저장 → `CRAWL_MEDIA_SAVED` ACK(저장 경로) → 항목 상태 완료 표시.
- 다운로드 폴더 변경 불가 → `chrome.downloads` 직접 저장 포기, **오프스크린 fetch → 서버 물리 저장** 채택. txt는 플러그인이 생성(서버는 원문 그대로 저장). 상한 없음.
- txt 포맷: `# WebCrawlServer 이미지 참조 파일` / `# 인출 방식: 플러그인 직접 다운로드 (오페라 VPN)` / page_url / image_url / click_url / title / [sfw_image_url] / [preview_video_url] / saved_files 목록.

## 처리 단계
1. `server/src/services/fileStorageService.ts`: 실패 참조 확장자 `.url`→`.txt`(전역), `SaveCrawledImageOptions`에 `clickUrl`/`title` 추가, `mimeToExtension`에 `video/mp4`/`video/webm→mp4` 추가, 신규 `saveCrawledMediaBundle()`(txt+자산 일괄 저장, 실패 자산 data 빈 문자열 스킵, `savedDir`/`savedFiles` 반환).
2. `server/src/index.ts`: `GET_STORAGE_LOCATION` 액션 신설(→`STORAGE_LOCATION_RESPONSE` absDir/relDir 응답). CRAWL_IMAGE 분기에서 `payloadObj.assets` 배열 감지 시 번들 저장 + `CRAWL_MEDIA_SAVED` ACK(bundleId/savedDir/savedFiles) 응답, 기존 단일 이미지 분기 유지.
3. `plugins/basic-plugin/src/types/index.ts`: `XvideosMediaEntry`/`MediaAssetPayload`/`CrawlMediaBundlePayload`/`StorageLocationRequestPayload`/`StorageLocationResponsePayload`/`CrawlMediaSavedAckPayload`/`XvideosDownloadStatus`/`XvideosDownloadItem` 신설.
4. `plugins/basic-plugin/src/content.ts`: 신규 `collectXvideosMediaEntries()`(`.thumb-block` 파싱, `resolveImageSource` 재사용, no-img/assets-cdn77 제외, `.videopv a`→closest a[href]→thumb a 순 clickUrl, `.thumb-under .title a[title]` 우선 title, eid 정규식 `/video\.([a-z0-9]+)\//i`) + `COLLECT_XVIDEOS_MEDIA` 명령 핸들러(entries+pageUrl 응답).
5. `plugins/basic-plugin/src/offscreen.ts`: `mediaAckWaiters` Map(bundleId→해소, 60초 타임아웃)/`storageLocationWaiter`(15초 타임아웃), `arrayBufferToBase64()`/`extractMediaFileName()`/`fetchAssetAsBase64()`(credentials:"omit", 실패 시 빈 data), `handleFetchMediaBundle()`(3자산 순차 인출→번들 전송→ACK 대기), `GET_STORAGE_LOCATION`/`FETCH_MEDIA_BUNDLE` 메시지 핸들러, `CRAWL_MEDIA_SAVED`/`STORAGE_LOCATION_RESPONSE` 수신 해소 로직.
6. `plugins/basic-plugin/src/services/chromeService.ts`: `requestCollectXvideosMedia()`/`requestStorageLocation()`/`requestFetchMediaBundle()` 신설.
7. `plugins/basic-plugin/src/hooks/usePopupState.ts`: xvideos 매니저 state 5종 + `extFromUrl`/`buildXvideosTxtContent`/`handleBuildXvideosDownloadList`/`handleStartXvideosDownloads`(순차 진행, done/failed 실시간 집계)/`handleResetXvideosDownloadList`, `getPacketLogType`에 `CRAWL_MEDIA_SAVED`/`STORAGE_LOCATION_RESPONSE` success 처리.
8. `plugins/basic-plugin/src/components/tabs/BasicTab.tsx`: Props 6종 추가, `getDownloadStatusInfo()`(대기/다운로드/완료/실패 배지), xvideos.com "normal" 버튼을 미디어 다운로드 목록 생성으로 연결, DownloadThemAll식 매니저 패널(저장 위치 절대경로/항목 상태 목록/진행·초기화 버튼) JSX 추가.
9. `plugins/basic-plugin/src/sidepanel.tsx`/`popup.tsx`: BasicTab에 xvideos 6종 props 전달.
10. **opera-plugin 동기화**: 변경 8종 복사 + 헤더 주석 교체(`background.ts`는 `chrome.sidePanel?.` 옵셔널 차이로 의도적 유지).
11. **문서**: R-00208 §2.1(참조 `.txt`/click_url·title 포맷)·§2.2(미디어 번들 저장 규격)·§3.1(`saveCrawledMediaBundle` API)·§5 체크리스트, R-00430 §5.4(xvideos 파싱)·§6, R-00420 §4.5(번들 통신 규격·ACK 대기)·§5 갱신.
