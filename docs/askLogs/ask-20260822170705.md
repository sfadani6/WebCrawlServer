# 작업 이력: 로컬 환경 OpenCode 설정 — 프로젝트 내부 세션 원장 기록 체계 구축 (ask-20260822170705)

## 요청 (사용자 지시 원문)
- 현재 로컬 환경에서 OpenCode를 설정해달라.
- 앞으로 모든 질문과 AI의 진행 절차, 출력된 로그 등이 프로젝트 안에서 기록되도록 해달라.

## 처리 단계
1. 루트 `opencode.json` 신설: `$schema`(opencode.ai/config.json), `instructions: ["AGENTS.md"]`, `logLevel: "INFO"`, `share: "disabled"`(세션 외부 공유 차단).
2. `.opencode/plugin/session-logger.ts` 플러그인 신규 작성:
   - `event` 훅으로 이벤트 버스 전체를 구독. 사용자 질문/응답 텍스트(`chat.text`), 도구 실행 상태(`chat.tool`), 세션·권한·파일 이벤트(`kind: "event"`)를 원장에 남긴다.
   - 고빈도 노이즈(`time.`/`lsp.`/`file.watcher.` 접두어)와 스트리밍 델타(`message.part.delta`)는 제외.
   - `message.part.updated`는 파트 ID 단위 버퍼 + 디바운스(텍스트 800ms / 도구 300ms, 스냅샷 동일 시 중복 억제)로 기록.
   - 출력 경로: `<프로젝트>/.opencode/logs/YYYY-MM-DD.jsonl` (일자 롤오버, 프로세스 exit 시 잔여 버퍼 동기 플러시).
   - R-00106 준수: 파일 경로 헤더 주석, 전 함수/상수 한글 JSDoc, ESM, `any` 미사용(`unknown` + 타입 좁히기).
3. `.gitignore` 무시 확인: `logs/` 패턴이 임의 깊이의 `logs` 디렉터리와 매칭되어 `.opencode/logs/` 원장은 자동 gitignore 대상(저장소 부담 없음).
4. `eslint.config.mts`: 최상위 ignores에 `.opencode/**` 추가 — tsconfig 프로젝트 범위 밖 파일이라 parserOptions.project 오류가 발생하는 것을 방지.

## 검증 결과
- esbuild 변환(es2022/esm) 통합 구문 검사 통과 — `node node_modules/esbuild/bin/esbuild .opencode/plugin/session-logger.ts --format=esm --target=es2022`.
- ESLint: `.opencode/plugin/session-logger.ts` 무시 패턴 적용(exit 0), `eslint.config.mts` 린트 문제 없음.
- tsc 영향 없음: 루트 tsconfig include는 server/admin/basic-plugin src뿐(.opencode 미포함).
- `git check-ignore -v .opencode/logs/test.jsonl` → `.gitignore:11 logs/` 매칭 확인.
- 실측 보류: OpenCode 재시작 후 세션 원장 파일 생성 여부는 다음 세션에서 자동 검증 가능.
