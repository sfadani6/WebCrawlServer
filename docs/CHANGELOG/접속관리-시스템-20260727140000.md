## 상세 변경 내용

### 1. `plugin/manifest.json`
- **변경 전**: web_accessible_resources 필드 없음
- **변경 후**: icons/* 리소스에 대한 web_accessible_resources 추가
- **변경 이유**: Opera 브라우저에서 확장 프로그램 아이콘을 로드할 수 있도록 Manifest V3 호환성 개선

### 2. `server/app.js`
- **변경 전**: verifyClient에서 chrome-extension:// 및 opera-extension://만 지원
- **변경 후**: moz-extension:// 추가 지원, async DB 체크 시 callback(true) 중복 호출 방지
- **변경 이유**: Firefox 확장 프로그램에서도 WebSocket 인증이 동작하도록 호환성 개선

### 3. `server/monitor/connectionManager.js` (신규)
- **기능**: WebSocket 연결 추적, 등록, 제거, 조회, 통계 기능 제공
- **주요 함수**:
  - registerConnection(): 새로운 연결 등록
  - unregisterConnection(): 연결 정보 제거
  - getAllConnections(): 현재 모든 연결 조회
  - terminateConnection(): 특정 연결 강제 종료
  - getConnectionStats(): 연결 통계 정보 조회
- **변경 이유**: 관리자 페이지에서 실시간으로 연결 상태를 모니터링할 수 있도록 연결 정보 추적 시스템 구현

### 4. `server/routes/admin.js` (신규)
- **기능**: 접속 관리 API 제공
- **엔드포인트**:
  - GET /admin/api/connections: 모든 연결 조회
  - GET /admin/api/connections/:id: 특정 연결 정보 조회
  - POST /admin/api/connections/:id/terminate: 연결 강제 종료
  - GET /admin/api/connections/stats: 연결 통계 조회
  - GET /admin/api/plugins/pending: 승인 대기 플러그인 조회
  - GET /admin/api/plugins/approved: 승인된 플러그인 조회
  - POST /admin/api/plugins/:id/approve: 플러그인 승인
  - POST /admin/api/plugins/:id/reject: 플러그인 거절
  - POST /admin/api/plugins/:id/disconnect: 플러그인 연결 종료
  - GET /admin/api/plugins/status/:requestId: 플러그인 상태 확인
- **변경 이유**: PluginsPage에서 사용하던 API를 관리자 API로 통일 및 새로운 접속 관리 API 제공

### 5. `server/admin-ui/src/components/ConnectionPage.jsx` (신규)
- **기능**: 실시간 접속 관리 페이지
- **주요 기능**:
  - 현재 연결된 모든 장비 및 플러그인 리스트 표시
  - 브라우저 아이콘, 이름, 버전, IP 주소, 연결 시간, 로그인 상태 표시
  - 자동 새로고침 (3~30초 간격 설정 가능)
  - 개별 연결 강제 종료 기능
  - 서버 연결 정보 패널 (WebSocket URL, 연결 수, 서버 상태)
- **변경 이유**: 사용자가 현재 시스템 상태를 실시간으로 모니터링할 수 있도록 접속 관리 페이지 구현

### 6. `server/admin-ui/src/components/Layout.jsx`
- **변경 전**: 접속관리 메뉴 없음
- **변경 후**: 📡 접속 관리 메뉴 항목 추가 (Cache Donald 아래에 위치)
- **변경 이유**: 사용자가 접속 관리 페이지에 쉽게 접근할 수 있도록 네비게이션 메뉴 추가

### 7. `server/admin-ui/src/App.jsx`
- **변경 전**: /connections 경로 라우팅 없음
- **변경 후**: /connections 경로 → ConnectionPage 연결
- **변경 이유**: 접속 관리 페이지 라우팅 설정

## 변경 이유

1. **Opera 브라우저 호환성**: 기존에는 Chrome과 Opera만 부분적으로 지원 देखकर, Manifest V3 표준을 준수하여 모든 브라우저에서 플러그인 아이콘이 정상적으로 로드되도록 개선

2. **WebSocket 인증 개선**: verifyClient의 async 처리 로직에서 callback이 중복 호출되는 문제를 해결하고, 모든 브라우저 확장 프로그램(Chrome, Opera, Firefox)을 지원하도록 개선

3. **접속 관리 기능 필요**: 관리자가 현재 서버에 연결된 모든 장비와 플러그인을 실시간으로 모니터링할 수 있는 기능이 필요하여 구현

4. **사용자 편의성 향상**: 접속관리 메뉴를 통해 현재 시스템 상태를 한눈에 확인할 수 있도록 UI 개선

---

## 영향을 미치는 부분

- **플러그인**: Opera 브라우저에서 정상적으로 동작
- **서버**: WebSocket 연결 추적 기능 추가로 slight한 메모리 사용량 증가 (연결 정보 저장)
- **관리자 UI**: 새로운 접속 관리 페이지 제공
- **API**: 새로운 /admin/api/connections 엔드포인트들 추가

---

## 테스트 방법

1. 플러그인을 Opera 브라우저에 설치하여 아이콘 로딩 확인
2. 플러그인에서 서버 연결 시 WebSocket 인증 정상 동작 확인
3. 관리자 페이지 `/connections`에 접속하여 연결 목록 표시 확인
4. 플러그인 연결 후 ConnectionPage에 연결 정보 표시 되는지 확인
5. 연결 종료 버튼으로 연결 강제 종료 되는지 확인
