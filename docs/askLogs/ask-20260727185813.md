## 요청 내용
사용자가 `/plugins` 화면에 채팅 창이 표시되고 플러그인 연결이 되지 않는 문제를 보고하였다.

## 수행된 작업
- `server/admin-ui/src/components/PluginsPage.jsx`에서 기능과 연결되지 않은 고정 채팅 UI, 관련 상태, 승인 폴링 중복 로직, 남아 있던 `</write_to_file>` 문자열을 제거하였다.
- 플러그인 관리 화면의 안내 문구를 실제 2단계 승인 흐름에 맞게 수정하였다.
- `plugin/background.js`에서 승인 토큰이 저장되어 있으면 새 승인 요청을 만들지 않고 바로 WebSocket 연결을 시도하도록 수정하였다.
- 승인 폴링으로 받은 토큰을 확장 프로그램 설정에 저장하도록 수정하였다.
- `plugin/options/options.js`에서 기본 토큰 입력값을 비워 승인 전 기본 토큰으로 잘못 연결 테스트를 시도하지 않도록 수정하였다.
- `server/monitor/connectionManager.js`에 플러그인 요청 ID 기준 WebSocket 연결 종료 함수를 추가하였다.
- `server/routes/plugin.js`, `server/routes/admin.js`의 연결 종료 API가 DB 상태 변경뿐 아니라 실제 WebSocket 연결도 종료하도록 수정하였다.

## 변경 이유
- `/plugins` 하단 채팅 UI는 플러그인 승인/연결 흐름과 연결된 기능이 아니며 화면을 가리고 혼선을 유발하였다.
- 승인 후 발급된 토큰을 수동 입력했더라도 기존 백그라운드 로직은 토큰을 사용하지 않고 새 승인 요청만 생성해 연결이 지연될 수 있었다.
- 연결 종료 API가 DB 상태만 변경하면 이미 열려 있는 WebSocket 세션은 유지되어 관리자 화면의 연결 관리 동작과 실제 연결 상태가 어긋날 수 있었다.

## 검증
- `node --check`로 변경한 JavaScript 파일의 구문을 확인하였다.
- `npm test -- --runInBand`를 실행했으나 기존 테스트 환경의 DB 잠금 및 빌드 산출물 누락 문제로 실패하였다.
- `npm --prefix server/admin-ui run build`는 관리자 UI 로컬 의존성 미설치로 실패하였다.
- `npm --prefix server/admin-ui ci`는 `marked`와 `@glideapps/glide-data-grid`의 peer dependency 충돌로 실패하였다.
- `npm --prefix server/admin-ui ci --legacy-peer-deps && npm --prefix server/admin-ui run build`는 의존성 설치가 장시간 완료되지 않아 중단하였다.
