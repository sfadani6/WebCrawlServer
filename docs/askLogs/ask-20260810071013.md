# 작업 이력: xvideos 단일 영상 페이지(플레이어) 포스터 이미지·타이틀 추출 (ask-20260810071013)

## 요청
- xvideos.com 미디어 다운로드에서 단일 영상 페이지(플레이어) DOM을 주고, "`<img src="https://thumbs-gcore.xvideos-cdn.com/.../xv_19_p.jpg">` 이부분도 추출해야되", "`Japanese horny unknown teen -what is her name ?` 이부분이 타이틀 일꺼야", "여긴 이미지 하나면되".

## 확정된 결괏값
- xvideos **단일 영상 페이지**(플레이어)에서 **포스터 이미지 1종 + 타이틀**을 추출해 다운로드 매니저 목록에 1건으로 포함한다. **이미지 1개만** 다운로드한다.
- 영상 자체(blob 스트리밍)는 다운로드하지 않는다.

## 처리 단계
1. `plugins/basic-plugin/src/content.ts`:
   - `isXvideosVideoPage()`: URL `/video` 접두사(`/^\/video(\d+|\.)/i`) 또는 플레이어 DOM(`#html5video`/`#hlsplayer`/`.video-bg-pic`/`.video-pic`) 존재로 단일 영상 페이지 판별.
   - `collectXvideosVideoPageEntry()`: 포스터 이미지 `.video-bg-pic .video-pic img`(resolveImageSource, no-img 제외) → `mainUrl`, 플레이어 영역 `.video-title` 텍스트 → `title`, 현재 페이지 URL → `clickUrl`, URL에서 EID 파싱. `sfwUrl`/`previewUrl`는 빈 문자열.
   - `COLLECT_XVIDEOS_MEDIA` 핸들러: `.thumb-block`이 0개이고 단일 영상 페이지이면 비디오 페이지 항목 1건으로 폴백, 응답 message에 소스(비디오 블록/현재 영상 페이지) 명시.
2. `plugins/basic-plugin/src/types/index.ts`: `XvideosMediaEntry.sfwUrl`/`previewUrl` JSDoc에 "단일 영상 페이지에서는 빈 문자열" 명시.
3. `plugins/basic-plugin/src/components/XvideosManagerView.tsx`: 빈 목록 안내 문구에 단일 영상 페이지(포스터 이미지 1종) 파싱 추가.
4. **기존 흐름 재사용**: 빈 `sfwUrl`/`previewUrl`는 오프스크린 `fetchAssetAsBase64("")`가 빈 데이터 반환 → 서버 `saveCrawledMediaBundle`의 `if (!asset.data) continue`로 건너뜀 → **이미지 1종 + txt만 저장**. txt(`buildXvideosTxtContent`)도 sfw/preview 라인 생략, 매니저 UI도 빈 자산 라인 미표시.
5. **opera-plugin 동기화**: `content.ts`/`types/index.ts`/`XvideosManagerView.tsx` 3종.
6. 문서: R-00430 §5.4(단일 영상 페이지 폴백), R-00420 §4.5(명령 규격), askLog 신규.
