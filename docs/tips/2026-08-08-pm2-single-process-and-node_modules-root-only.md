# PM2 프로세스 1개 정상 여부 및 node_modules 루트 고정 (2026-08-08)

`docs/ask.md` 요청("npm run admin:start 후 server:start 하면 하나만 떠 있어", "admin/node_modules가 생기면 안 된다")에 대한 원인과 해결을 정리한 문서입니다.

## 1. 요약

| 증상 | 결론 |
|---|---|
| `npm run admin:start` 후 `npm run server:start`를 실행해도 PM2에 `WebCrawlServer` 하나만 존재 | **정상 동작** — 두 명령 모두 결국 동일한 단일 서버 프로세스만 관리하도록 설계됨 |
| `admin/` 디렉토리에 `node_modules`가 생성됨 | 실체는 **Vite 의존성 최적화 캐시(`node_modules/.vite`)** — `vite.config.ts`의 `cacheDir` 설정으로 해소됨 |

## 2. PM2 프로세스가 하나만 뜨는 이유

### 2.1 명령 실행 흐름

루트 `package.json`의 스크립트는 아래와 같이 연결됩니다.

```
npm run admin:start
  └─ npm run --workspace=admin build          (admin Vite 빌드 → server/public)
      └─ npm run --workspace=server server:start
          └─ node server/scripts/start-server.js

npm run server:start
  └─ npm run --workspace=server server:start
      └─ node server/scripts/start-server.js
```

즉 `admin:start`는 **"admin 최신 빌드 선행 + 서버 시작"**, `server:start`는 **"서버 시작"** 만의 차이이며, 두 명령 모두 `server/scripts/start-server.js`를 실행합니다.

### 2.2 `start-server.js`의 단일 프로세스명 관리

`server/scripts/start-server.js`는 항상 아래 순서로 동작합니다.

1. `server/` 기준으로 TypeScript 빌드(`tsc -p tsconfig.json`)
2. `pm2 delete WebCrawlServer` (기존 프로세스 정리, 없으면 무시)
3. `pm2 start dist/index.js --name WebCrawlServer` (동일 이름으로 단일 기동)

`--name WebCrawlServer`가 하드코딩되어 있으므로 `admin:start`를 몇 번을 실행하든, 그 후 `server:start`를 실행하든 **항상 PM2에는 `WebCrawlServer` 1개만 존재**합니다. 2개가 떠 있는 것은 오히려 비정상입니다.

### 2.3 포트 자동 이동 결함과 개선 (서버 재실행 시 9600 고정)

기존 `start-server.js`에는 `getAvailablePort(9600)` 로직이 있어, **9600이 이미 기동 중인 서버에 점유되어 있으면 9601로 자동 이동**한 뒤 `pm2 delete`로 기존 서버를 죽이고 새 서버를 9601에서 기동하는 결함이 있었습니다.

- 재현 시나리오: `npm run admin:start`(9600 기동) → `npm run server:start` 재실행 → 기존 서버 제거 후 **9601에서 기동** → PM2에는 하나만 보이는데 `http://localhost:9600/` 접속은 실패.
- 해결: `getAvailablePort()`를 제거하고 `SERVER_PORT`(기본 9600) **고정 포트**로 단일 운영합니다.
- 개선 후: `server:start`를 몇 번을 재실행해도 항상 `WebCrawlServer` 1개 + **9600 고정**으로 재기동됩니다. 포트를 바꾸려면 `SERVER_PORT` 환경 변수로 명시해야 합니다.

### 2.4 admin 대시보드는 별도 프로세스가 아님

- 관리자 대시보드(admin)는 **별도 PM2 프로세스가 아니라** 서버(`server/src/index.ts`)가 `server/public/` 디렉토리를 정적 서빙하는 형태입니다.
- 접속 주소: `http://localhost:9600/`
- 따라서 `pm2 list`에 admin 전용 프로세스가 보이지 않는 것은 정상입니다.

### 2.5 잔재 스크립트 정리 (`WebCrawlAdmin`)

이전에는 루트 `package.json`에 존재하지도 않는 프로세스명 `WebCrawlAdmin`을 참조하는 `admin:status`/`admin:logs`/`admin:stop` 스크립트가 남아 있었으나, **2026-08-08 정리로 제거**되었습니다. 현재 관리 대상은 `WebCrawlServer` 하나이며 상태/로그/중지는 `server:status`/`server:logs`/`server:stop`을 사용합니다.

## 3. admin/node_modules가 생성되는 원인과 해결

### 3.1 원인: Vite의 기본 `cacheDir`

- Vite는 의존성 최적화 캐시(deps 캐시)를 기본적으로 `node_modules/.vite`에 저장합니다.
- `cacheDir`의 기본 경로는 **Vite가 실행되는 디렉토리 기준**입니다.
- `npm run --workspace=admin build`는 `cwd`를 `admin/`로 하여 Vite를 실행하므로, `admin/node_modules/.vite`가 생성되었습니다. 이것이 "admin/node_modules가 생긴다"의 정체입니다.
- `server/node_modules`, `plugins/basic-plugin/node_modules`는 실제 패키지가 없는 **빈 폴더**입니다(실패키지는 npm workspaces에 의해 루트 `node_modules`에만 호이스팅됨).

### 3.2 해결: `cacheDir`을 프로젝트 루트로 명시

두 워크스페이스의 `vite.config.ts`에 캐시 경로를 명시하여 워크스페이스 하위에 `node_modules`가 생성되지 않도록 했습니다.

```typescript
// admin/vite.config.ts — 프로젝트 루트 node_modules/.vite 공유
cacheDir: resolve(__dirname, "../node_modules/.vite"),

// plugins/basic-plugin/vite.config.ts
cacheDir: resolve(__dirname, "../../node_modules/.vite"),
```

이제 `npm run build --workspace=admin` 또는 `--workspace=basic-plugin`을 실행해도 워크스페이스 디렉토리에 `node_modules`가 생기지 않습니다.

### 3.3 정리 방법

이미 생성된 워크스페이스 node_modules는 아래 중 하나로 삭제합니다.

```bash
# 루트 package.json의 전용 스크립트 사용
npm run clean:admin-modules

# 또는 수동 삭제
Remove-Item -Recurse -Force admin/node_modules
Remove-Item -Recurse -Force server/node_modules
Remove-Item -Recurse -Force plugins/basic-plugin/node_modules
```

## 4. 예방 규칙

- `npm install` / `npm ci`는 **반드시 프로젝트 루트에서만** 실행합니다. 워크스페이스 내부(예: `cd admin && npm install`)에서 설치하면 해당 워크스페이스에 별도 `node_modules`가 생성됩니다.
- `node_modules`는 프로젝트 루트에만 존재해야 하며, 각 워크스페이스의 `node_modules`가 새로 생겼다면 Vite `cacheDir` 생성 여부를 먼저 확인합니다(실패패키지 호이스팅이 아님).
- `.gitignore`에는 `node_modules/`, `**/node_modules/`, `.vite/`가 이미 등록되어 있어 git 트래킹 대상이 아닙니다.
- 서버가 이미 9600에서 기동 중일 때 `server:start`/`admin:start`를 재실행해도 **동일 프로세스 + 9600 고정**으로 재기동됩니다. 포트를 옮기려면 `SERVER_PORT` 환경 변수로 명시합니다.
