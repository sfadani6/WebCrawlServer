## 1. 작업 흐름도 (강제 규정)

```
docs/ask.md (요청 기록)
    ↓
docs/todo.md (계획 등록)
    ↓
각 항목별 실행 (1개 항목 = 1개 askLogs 파일)
    ↓
docs/askLogs/ask-YYYYMMDDHHMMSS.md (각 항목별 처리 내역 + 결과)
    ↓
docs/todo.history.md (처리 이력 기록)
    ↓
docs/todo.md (완료 항목 제거)
    ↓
docs/CHANGELOG.md (변경사항 요약)
    ↓
docs/CHANGELOG/처리항목-YYYYMMDDHHMMSS.md (변경사항 상세)
    ↓
docs/ask.md (비우기)
    ↓
Git 커밋
```

> **중요**: 위 흐름은 AI가 작업을 수행할 때 반드시 따라야 하는 **강제 규정**이다. 단계를 건너뛰거나 순서를 변경할 수 없다.

## 2. 파일별 역할 (강제 규정)

### docs/ask.md
- 작업 요청을 자유 형식으로 기록한다.
- **처리 완료 후 반드시 비운다.** (`docs/ask.md`는 빈 파일 또는 초기 상태로 재설정)
- ask.md가 비어있지 않으면 AI는 작업을 계속 진행 중인 것으로 간주한다.

### docs/todo.md
- AI가 실행할 작업 계획을 구체적 단계로 기록한다.
- 각 항목은 상태(`🟡 진행 전`, `🔴 진행 중`, `✅ 완료`)로 관리한다.
- **완료된 항목은 상태를 갱신하지 않고 반드시 목록에서 제거(삭제)한다.**
- 착수하지 않았거나 보류된 항목을 완료로 잘못 표시하지 않으며, 실제 진행 상태와 문서 내용이 어긋난 채 방치하지 않는다.

### docs/todo.history.md
- 완료된 작업의 요약과 상세 이력 파일 링크를 기록한다.
- 포맷: 완료 일시(YYYY-MM-DD HH:MM:SS), 항목명, askLogs 파일명, 결과 요약.

### docs/askLogs/ask-YYYYMMDDHHMMSS.md
- **각 작업 항목별로 1개의 로그 파일을 생성한다.**
- 1개의 ask에 여러 항목이 있으면 항목 개수만큼 askLogs 파일을 생성한다.
- 필수 포함 내용:
  - 요청 정보 (로그 생성 일시, 관련 문서, 요청 유형)
  - 수행된 작업 (변경 내용, 파일 위치, 기능 상세)
  - Task Completed 내용 (체크 항목, 상태, 비고)
  - ask.md의 처리 결과 기록
  - 관련 Rule ID
  - 변경 이유

### docs/CHANGELOG.md
- 처리한 항목의 변경사항을 요약하여 기록한다.
- 버전별 또는 일자별로 변경 로그를 관리한다.

### docs/CHANGELOG/처리항목-YYYYMMDDHHMMSS.md
- 각 처리 항목별 상세 변경 내역을 기록한다.
- 파일명: `처리항목명-YYYYMMDDHHMMSS.md` (예: `cronParser-20260726200000.md`)
- 필수 포함 내용:
  - 변경 개요
  - 변경된 파일 목록
  - 각 파일별 상세 변경 내용
  - 변경 이유

## 3. 운영 절차 (강제 규정)

1. `docs/ask.md`에 요청을 기술한다.
2. `docs/todo.md`에 계획을 작성한다 (우선순위, 실행 단계 포함).
3. 각 항목을 순차적으로 실행한다:
   3a. 해당 항목에 대한 `docs/askLogs/ask-YYYYMMDDHHMMSS.md`를 생성한다.
   3b. 항목 실행 및 변경사항을 적용한다.
   3c. askLogs 파일에 처리 내역, 결과, 변경 이유를 기록한다.
4. `docs/todo.history.md`에 처리 이력을 기록한다.
5. `docs/todo.md`에서 완료된 항목을 **제거(삭제)**한다.
6. `docs/CHANGELOG.md`에 변경사항 요약을 기록한다.
7. `docs/CHANGELOG/처리항목-YYYYMMDDHHMMSS.md`에 상세 변경 내역을 기록한다.
8. `docs/ask.md`를 **비운다** (초기 상태로 재설정).
9. 설계 결정이 있었던 작업이면 6장 기준에 따라 ADR 작성 여부를 판단한다.
10. 모든 변경사항을 Git 커밋한다.

## 4. AI 자동 이력 관리 절차 (AI 전용, 강제 규정)

> **목적**: 모든 AI 에이전트가 동일한 이력 관리 절차를 자동으로 수행하도록 표준화
> **적용 대상**: 모든 AI 작업 완료 후 자동 수행
> **위반 시**: 다음 작업 시작 시 불완전한 상태로 간주되어 선처리 필요

### AI 자동 수행 체크리스트 (필수)

- [ ] **askLogs 로그 파일 생성** (각 항목별 1개)
  - 파일명: `ask-YYYYMMDDHHMMSS.md`
  - 위치: `docs/askLogs/`
  - 필수 포함: 요청 정보, 수행된 작업, Task Completed, ask.md 처리 결과, 변경 이유

- [ ] **todo.history.md 업데이트**
  - 이력 포맷: `[완료] HH:MM:SS - 작업 이름 (askLogs: 파일명)`
  - 내용 포함:
    - 작업 항목
    - 변경 내용 (Bullet list)
    - 변경 이유
    - 결과
    - 관련 Rule
    - 담당 AI
  - 통계 갱신:
    - 총 이력 수 +1
    - 완료된 작업 수 +1
    - 마지막 업데이트 시간 갱신

- [ ] **todo.md 완료 항목 제거**
  - 완료된 작업을 목록에서 **삭제** (상태 변경 아님)
  - 다음 우선순위 작업 유지

- [ ] **CHANGELOG.md 업데이트**
  - 변경사항 요약 기록

- [ ] **CHANGELOG/ 상세 로그 생성**
  - 파일명: `처리항목-YYYYMMDDHHMMSS.md`
  - 위치: `docs/CHANGELOG/`

- [ ] **ask.md 비우기**
  - 파일 내용을 초기화한다

- [ ] **Git add/commit(및 필요 시 push) 완료**

## 5. 작업 종료 체크리스트

작업을 "완료"로 표시하기 전 아래 항목을 모두 확인한다. 하나라도 미완료 상태면 완료로 표시하지 않는다.

- [ ] 코드 컴파일/실행 확인
- [ ] Lint/포맷 확인(프로젝트에 도구가 설정된 경우)
- [ ] `coding.md`(R-011) 코드 작성 규칙 위반 여부 확인
- [ ] 관련 로그(`logs/`, `activity_logs`, `error_logs`) 확인
- [ ] 각 항목별 `docs/askLogs/ask-YYYYMMDDHHMMSS.md` 생성 완료
- [ ] `docs/todo.history.md` 기록 완료
- [ ] `docs/todo.md`에서 완료 항목 **제거** 완료
- [ ] `docs/CHANGELOG.md` 변경사항 기록 완료
- [ ] `docs/CHANGELOG/처리항목-YYYYMMDDHHMMSS.md` 상세 기록 완료
- [ ] `docs/ask.md` 비우기 완료
- [ ] 설계 결정 사항이 있었다면 6장 기준으로 ADR 작성 여부 확인
- [ ] Git add/commit(및 필요 시 push) 완료

## 6. ADR(Architecture Decision Record) 작성 규정

"왜 A 대신 B를 선택했는지"를 남기지 않으면 이후 같은 논의가 반복될 수 있다. 아래 기준에 해당하는 작업은 ADR을 남긴다.

### 6.1 작성 대상
아래 중 하나에 해당하면 ADR을 작성한다.
- 대안이 2개 이상 있었고, 그중 하나를 선택한 근거를 남길 필요가 있는 경우(예: 특정 라이브러리 채택, 스키마 구조 선택, 워크플로우 제어 구조 설계)
- 규칙 문서(`docs/rule/` 하위 문서)의 기존 결정을 뒤집는 변경인 경우
- 되돌리기 어렵거나 비용이 큰 구조 변경인 경우

단순 버그 수정, 오탈자 수정, 문서 경로 정정처럼 대안 비교가 필요 없는 작업은 ADR 대상이 아니다. 이 경우 `docs/askLogs/`의 변경 이유 기록으로 충분하다.

### 6.2 작성 위치 및 형식
- 위치: `docs/decision/`
- 파일명: `NNNN-짧은-제목.md` (예: `0001-module-structure.md`), 번호는 4자리 일련번호로 순차 부여한다.
- 최소 포함 항목: 제목, 상태(제안/채택/폐기), 배경(문제 상황), 검토한 대안, 선택한 대안과 근거, 영향 범위.
- `docs/decision/`은 `AGENTS.md` 2장의 컨텍스트 로딩 예외 규칙과 동일하게 취급한다.

### 6.3 규칙 문서와의 관계
- ADR은 결정의 "기록"이고, `docs/rule/` 하위 문서는 결정의 "현재 유효한 규칙"이다. 두 문서의 역할이 다르므로, ADR을 작성했다고 규칙 문서 갱신을 생략하지 않는다. 규칙에 반영해야 하는 내용은 반드시 해당 `docs/rule/*.md` 파일도 함께 갱신한다.
